# Support

Use this page to find the correct support path quickly. H3P apps have different release channels, so access requests, app bugs, documentation problems, and security reports should be handled separately.

## Start here

1. Open the app from the [catalogue](/apps/index).
2. Read its **Installation**, **Known Issues**, and **FAQ** pages.
3. Check the [combined changelog](/changelog) for recent changes.
4. If the answer is not there, [send a support request](/support/support-and-feedback).

## Choose the right path

| Need | Use |
| --- | --- |
| Request TestFlight, private-beta, or alpha access | [Support and Feedback](/support/support-and-feedback) |
| Report an app behavior or installation problem | [Support and Feedback](/support/support-and-feedback) |
| Report a documentation or website problem | [appsh3p GitHub issues](https://github.com/h3pdesign/appsh3p/issues) |
| Report a Neon Vision Editor issue | [Neon Vision Editor issues](https://github.com/h3pdesign/Neon-Vision-Editor/issues) |
| Ask a question using published documentation | [Docs assistant](/support/docs-assistant) |
| Report a vulnerability | [Security and Trust](/policies/security-and-trust) |

## What support can resolve

Support can help with access, installation, permissions, documented workflows, reproducible app behavior, and documentation corrections. Requests are triaged by security impact, data-loss risk, reproducibility, and whether the issue blocks normal use.

Support cannot grant access to a private repository or disclose private release material through a public issue. Security reports should always use the private disclosure route.

## Privacy and security

- Read [Privacy Policy](/policies/privacy-policy) and [Terms of Service](/policies/terms-of-service) for site-level information.
- Read [AI and Data](/policies/ai-and-data) for AI and local-first data handling.
- Use [Security and Trust](/policies/security-and-trust) for vulnerability reporting.
